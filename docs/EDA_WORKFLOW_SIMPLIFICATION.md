# EDA workflow simplification

Date: 2026-10-18. Dataset-wide exploratory profiling now belongs to ingestion. This change removes automatic, generic profiling from question analysis while preserving result validation and the existing API response shape.

1. **Files inspected.** `app/workflow/{graph,recovery,runtime,reliability,state}.py`, `app/governed/{analysis,workflow,service,api,report}.py`, `app/analytics/{eda,result_validator,cache,insight_evidence}.py`, `app/api/{analytics,ingestion,database}.py`, `app/ingestion/{analyzer,quality_checker,schema_inference,mysql_loader}.py`, the report renderer, graph/ingestion/report tests, README, and architecture diagrams.
2. **Files modified.** `app/workflow/{graph,recovery,runtime,reliability}.py`, `app/governed/{analysis,workflow}.py`, `app/api/analytics.py`, `app/reporting/safe_pdf.py`, `tests/{test_clinical_langgraph,test_governed,test_reliability}.py`, `README.md`, `docs/IMPLEMENTATION.md`, `docs/architecture.mmd`, `docs/architecture.svg`, the two historical checklist/report documents, and `scripts/render_architecture.py`. No frontend, database schema, clinical records, SQL rules, or model configuration changed.
3. **Ingestion EDA retained.** Upload and analysis still run file/schema validation, type and column profiling, missing/blank statistics, duplicate detection, descriptive summaries, quality flags, relationship inference, and metadata registration. The ingestion implementation was not altered. Dataset-version identities continue to scope analysis and Redis cache entries.
4. **Intermediate EDA removed.** The default graph's `run_eda` node previously called `assess_results` on every validated query result and gated insight generation; it was removed. Cache population moved to the existing `validate_results` node after successful validation. Cache-hit revalidation no longer performs a second EDA pass. `POST /analytics/report/pdf` now runs only result validation, rather than repeating generic EDA during report creation. In the governed path, `Extractor.extract` no longer runs per-table null and duplicate-key profiling queries for each question; the legacy `eda` stage now creates only exact result-cell references and checks numerical invariants, without descriptive summaries or a generic quality-review interrupt. Its artifact key remains `eda` to preserve saved API and checkpoint contracts.
5. **Result validation intact.** SQL AST/table safety, read-only execution, result shape/type/denominator/grain checks, bounded result correction and revalidation, insight grounding, chart validation, PDF validation, and recovery remain. Invalid results still stop before insight generation. Cached rows are revalidated before use. Report submission rejects invalid rows.
6. **Question-specific analytics intact.** SQL aggregations and approved clinical templates still calculate counts, rates, trends, and group comparisons requested by the user. `build_insight_evidence` and governed result-cell references support factual interpretation; neither is generic dataset profiling.
7. **Graph changes.** The default route is `execute_sql → validate_results → generate_insight`; `run_eda` and its review edge were removed. The governed route is still `sql → eda → insights` at the legacy stage-name/API layer, but the active `eda` node now performs result evidence construction only; its separate quality gate is no longer invoked. Plan and final clinical review gates remain. The Mermaid and SVG views reflect ingestion-only EDA.
8. **Tests.** The combined workflow, ingestion, report, and recovery run passed **122/122** (`eda-removal-final.xml`). A final focused smoke run after the last code edit passed **38/38** (`eda-final-smoke.xml`). The live-MySQL analysis and follow-up run passed **31/31** (`eda-live-integration.xml`); a direct `SELECT 1` connection probe also succeeded. The SQL regression run passed **68/69** (`eda-sql-regression.xml`): the sole failure is an existing hard-coded expectation of 2,518 serious adverse events against a configured database that returns 2,517. This same mismatch was recorded before this change in `RELIABILITY_REPORT.md`; SQL generation and data were not changed here. Frontend tests passed **23/23**. Added assertions verify that generic EDA is not called during analysis or report generation, cache writes follow successful validation, and governed analysis does not issue source-profiling SQL. No real Redis service test is claimed.
9. **Limitations.** This does not attach an ingestion quality report to every governed analysis; its catalog currently carries dataset versions but not a full ingestion profile. The legacy governed artifact key `eda` remains for compatibility even though it no longer runs EDA. Old persisted analyses stopped at the removed default `run_eda` stage should be restarted under the new graph. The live MySQL tests exercised the configured local dataset, not a clinical production deployment. Active RAG retrieval was already absent in this checkout; this task did not add or remove RAG code.
